Kirim `PUT` Tanpa Satu Field? | Field-nya Bisa Hilang
5 method HTTP, plus beda PUT dan PATCH yang sering ketuker.
---
[code]
`PUT`: ganti seluruh data
Isi yang kamu kirim dianggap versi lengkapnya. Field yang tidak dikirim bisa ikut hilang.
```
PUT /users/7
{ "name": "Rina", "age": 26 }
```
---
[code]
`PATCH`: ubah sebagian
Kirim bagian yang mau diubah saja. Field lain tetap.
```
PATCH /users/7
{ "age": 26 }
```
---
[code]
`GET`: ambil data
Cuma membaca, tidak mengubah apa pun di server. Aman dipanggil berkali-kali.
```
GET /users/7
```
---
[code]
`POST`: buat data baru
Biasanya dibalas `201 Created`. Dikirim dua kali, bisa jadi dua data.
```
POST /users
{ "name": "Rina", "age": 25 }
```
---
[code]
`DELETE`: hapus data
Sering dibalas `204 No Content`: berhasil, tanpa isi balasan.
```
DELETE /users/7
```
---
Idempotent itu apa?
Dikirim sekali atau lima kali, hasil akhirnya di server sama. `GET`, `PUT`, dan `DELETE` idempotent. `POST` tidak. `PATCH` tergantung isinya.
---
Kenapa itu penting?
Kalau koneksi putus sebelum ada balasan, request idempotent aman dikirim ulang. `POST` jangan diulang otomatis: bisa bikin pesanan dobel.
